# 处理任务与文件恢复

## 任务接口

以下接口继续使用统一 `data` 响应封装和管理鉴权：

| 接口 | 权限 | 行为 |
| --- | --- | --- |
| `GET /api/v1/assets/workflows` | `assets.update` | 可执行工作流摘要，不含 GraphJson |
| `GET /api/v1/assets/storage-targets` | `assets.create` | 可写目标摘要，不含路径、连接配置或凭据 |
| `GET /api/v1/assets/{id}/jobs` | `assets.read` | 最近 50 个图片处理任务 |
| `POST /api/v1/assets/{id}/jobs/{jobId}/retry` | `assets.update` | 将失败任务重新排队，成功返回 204 |
| `GET /api/v1/assets/{id}/derivatives/{kind}/content` | `assets.read` | 受保护衍生物下载，含保留原图 |

工作流排队接口保留原有字段并增加 `jobId`。任务包含 `id`、`assetId`、`status`、`attempts`、`createdAtUtc`、`updatedAtUtc`、`errorMessage`。

## 状态与重试

任务持久化到 PostgreSQL。待执行状态为 `pending`，领取后为 `running`，完成后为 `succeeded` 或 `failed`。领取使用短事务，运行租约为两分钟、每二十秒续期；多个实例不会重复领取有效租约。处理队列达到 1000 个待执行/执行中任务时拒绝继续排队。

重启后，尚未领取的任务可继续执行。租约过期的图片处理任务标记失败，由用户核对图片后手动重试。重试会重新执行整个工作流，水印等步骤可能重复作用；当前不承诺逐步骤恰好执行一次。工作流仍按保存的节点顺序线性执行。

文件删除使用独立清理任务。数据库中的删除和待删对象清单一同提交，提交后立即尝试物理删除；失败时清单保留，后台以退避间隔自动重试。对象已经不存在时删除仍可成功。删除 API 的成功表示资产已退出业务查询，存储故障时物理清理可能稍后完成。

## 存储和原图

已被资产或未完成清理任务引用的存储 profile，不能直接修改目录、桶或仓库等位置字段；仍可修改显示名称、轮换凭据和调整公开代理地址。切换到新位置应创建新的 profile；旧资产不会自动迁移。

格式转换的 `KeepOriginal=true` 将旧文件登记为 `original_{id}` 衍生物，在详情中下载。删除资产时这份原图也进入清理清单。

修改原图会失效旧缩略图和 caption；已有缩略图会重新生成。需要 caption 时重新运行对应技能。

## 恢复边界

普通异常和取消路径会补偿文件写入，失败步骤和执行日志使用隔离的数据库上下文。删除与旧文件清理有持久化恢复记录。

水印和 Exif 清理仍保持同存储 key 覆盖的既有接口行为。进程在覆盖完成、数据库提交之前骤停时，内存中的原文件备份无法用于自动恢复。上传在对象存储完成、数据库提交之前遭遇进程骤停，也可能留下未登记对象。部署级备份和对象核对仍然必要；当前没有跨数据库与对象存储的分布式事务。
